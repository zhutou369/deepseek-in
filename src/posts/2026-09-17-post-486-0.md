## 教學開始：三步用 DeepSeek 自動優化網站

這個教學我們用 DeepSeek-V2 模型來做示範，不過其他的 DeepSeek 模型或者支援 DeepSeek API 的本地模型（比如用 Ollama 部署的）理論上也是通用的。為了讓你更容易上手，我會預設你對 Python 有點基礎，也懂點命令行操作。

### 第一步：準備 DeepSeek 模型及本地環境（用 Ollama）

首先，你需要一個能跟 DeepSeek 聊天的環境。你可以走 DeepSeek API 路線，或者在本地跑它的模型。對我們這些中小站長來說，本地運行能省下 API 費用，數據私隱也更有保障，所以我強推用 Ollama 來部署。我上週剛升級了我的 Mac mini，就在上面用 Ollama 部署了 DeepSeek-V2，跑起來效果嘎嘎好！

1.  **裝 Ollama：** 沒裝的同學，去 [Ollama 官網](https://ollama.com/) 下載安裝，選你系統對應的版本。
2.  **下 DeepSeek 模型：** 打開終端機，敲下這行命令下載 DeepSeek-V2 模型：
    ```bash
    ollama run deepseek-coder
    ```
    當然你也可以選其他 DeepSeek 模型。這命令會自動下載並啟動模型。如果你就是要用 DeepSeek API，那就直接去申請個 API Key 唄。
3.  **裝 Python 依賴：** 我們需要 `requests` 庫來跟 Ollama 本地服務或 DeepSeek API 對話。執行：
    ```bash
    pip install requests
    ```

### 第二步：編寫自動化腳本和優化提示詞

這一步是關鍵！我們用 Python 寫個小腳本，它會讀取你網站的 HTML、CSS、JavaScript 文件，接著把內容丟給 DeepSeek 優化，最後再把優化後的內容寫回文件。

**示例 Python 腳本 `optimize_site.py`：**

```python
import os
import requests

# 配置 DeepSeek 服務 (選擇 Ollama 本地服務或者 DeepSeek API)
# 如果用 Ollama，URL 係 http://localhost:11434/api/generate
# 如果用 DeepSeek API，URL 係 https://api.deepseek.com/chat/completions
# 同埋需要 header 設置 API Key

# Ollama 配置範例
OLLAMA_URL = "http://localhost:11434/api/generate"
MODEL_NAME = "deepseek-coder"
USE_OLLAMA = True # 如果用 DeepSeek API，請設為 False

# DeepSeek API 配置範例 (如果你選擇用 DeepSeek API)
DEEPSEEK_API_URL = "https://api.deepseek.com/chat/completions"
DEEPSEEK_API_KEY = "YOUR_DEEPSEEK_API_KEY" # 替換為你嘅 DeepSeek API Key

# 定義網站根目錄 (替換為你嘅實際路徑)
SITE_ROOT = "./my_website_project"
OUTPUT_DIR = "./optimized_website"

def send_to_deepseek(prompt_content, file_type):
    """向 DeepSeek 發送請求並獲取優化結果"""
    messages = [
        {"role": "system", "content": f"你係一個專業嘅前端優化助手。你嘅目標係將以下嘅 {file_type} 程式碼進行極度壓縮同清理宂餘，確保功能不變，但體積最小化。移除所有註釋、空白、縮短變數名（如果可以且安全）。只返回優化後嘅程式碼。"},
        {"role": "user", "content": prompt_content}
    ]

    if USE_OLLAMA:
        data = {
            "model": MODEL_NAME,
            "prompt": "\n".join([m['content'] for m in messages]), # Ollama prompt 格式可能唔同，需要調整
            "stream": False
        }
        response = requests.post(OLLAMA_URL, json=data)
        # Ollama 返回格式較為複雜，需要解析 'response' 字段
        # 呢度為咗簡潔，我地假設可以從 'response' 中直接抽取出文本
        return response.json()['response'] # 實際需要更複雜嘅解析
    else:
        headers = {
            "Authorization": f"Bearer {DEEPSEEK_API_KEY}",
            "Content-Type": "application/json"
        }
        data = {
            "model": "deepseek-chat", # DeepSeek API 可能用 deepseek-chat 或者 deepseek-coder
            "messages": messages,
            "stream": False
        }
        response = requests.post(DEEPSEEK_API_URL, headers=headers, json=data)
        return response.json()['choices'][0]['message']['content']

def optimize_file(filepath):
    """讀取文件，優化，並寫入新文件"""
    file_type = filepath.split('.')[-1]
    if file_type not in ['html', 'css', 'js']:
        return

    print(f"處理中: {filepath}")
    with open(filepath, 'r', encoding='utf-8') as f:
        content = f.read()

    optimized_content = send_to_deepseek(content, file_type)
    
    # 創建輸出目錄
    relative_path = os.path.relpath(filepath, SITE_ROOT)
    output_filepath = os.path.join(OUTPUT_DIR, relative_path)
    os.makedirs(os.path.dirname(output_filepath), exist_ok=True)

    with open(output_filepath, 'w', encoding='utf-8') as f:
        f.write(optimized_content)
    print(f"優化完成: {output_filepath}")

def main():
    if not os.path.exists(OUTPUT_DIR):
        os.makedirs(OUTPUT_DIR)

    for root, _, files in os.walk(SITE_ROOT):
        for file in files:
            optimize_file(os.path.join(root, file))
    print("所有文件優化完成！")

if __name__ == "__main__":
    main()
```

**提示詞（Prompt）要點：** 在 `send_to_deepseek` 函數裡，我們定義了「系統提示詞」和「用戶提示詞」。系統提示詞超級重要，它告訴 DeepSeek 你的角色和任務。我親測發現，明確告訴它要「極度壓縮」、「清理冗餘」、「確保功能不變」、「只返回優化後程式碼」這些關鍵詞，能讓 DeepSeek 的輸出結果更符合我們的預期。

### 第三步：執行腳本、監控成果並持續改進

1.  **先測腳本：** 第一步，務必在一個備份過的網站目錄裡測試！可以先挑一兩個文件優化，確認效果沒問題。
2.  **跑起來：** 打開終端機，`cd` 到你存 `optimize_site.py` 的目錄，然後執行：
    ```bash
    python optimize_site.py
    ```
    腳本會自動掃描 `SITE_ROOT` 下所有符合條件的文件，然後把優化後的版本存到 `OUTPUT_DIR`。
3.  **看效果：** 腳本跑完後，你會得到一個 `optimized_website` 目錄，裡面就是「瘦身」後的網站文件。你可以用 `diff` 工具或手動對比下優化前後的差異，看看 DeepSeek 有沒有犯傻，比如誤刪了啥重要程式碼。

4.  **性能測評：** 把優化後的網站部署到測試環境，然後用 Google PageSpeed Insights、GTmetrix 或 Lighthouse 這些工具測一測性能。對比下優化前後的分數，你會發現載入時間嘩啦啦地縮短，分數蹭蹭往上漲！
5.  **不斷優化：** 這個腳本只是個開始。你可以根據自己網站的特點，微調 DeepSeek 的提示詞，比如更明確地要求它別動某些關鍵邏輯，或者在特定情況下保留註釋。你還能加入圖片壓縮、快取設置等其他優化步驟，把它打造成一個更全面的自動化工作流。

## 我測試時發現的小貼士

DeepSeek 優化程式碼雖然方便，但它也不是神仙，不能包治百病。我在測試我的個人作品集網站時，總結了這幾點小貼士：

*   **備份先行：** 每次跑腳本前，**務必備份原始網站文件！** 萬一 DeepSeek 「優化過度」搞出 Bug，你也能馬上還原。
*   **逐步測試：** 別想著一口吃成胖子，不要一次性優化所有文件。可以先從 CSS 或不那麼重要的 JS 文件入手，看看效果，再慢慢擴大範圍。特別是那些複雜的 JavaScript 邏輯，我都會格外謹慎，確保壓縮後功能一切正常。
*   **限制輸入長度：** 大文件一次性發給 DeepSeek，可能會超出它的上下文窗口限制，或者處理時間超級久。對於特別大的 JS 或 CSS 文件，可以考慮分塊處理，或者先用傳統的 Minifier 工具做個基礎壓縮，再讓 DeepSeek 進行深度清理。
*   **本地模型硬體要求：** 如果你打算長期在本地用 Ollama 部署大型模型（比如 DeepSeek-V2），**媽呀，你電腦最好搞張強勁的顯示卡（GPU）！** 因為 LLM 運行起來非常吃資源。不然只用 CPU 跑會慢很多，甚至讓電腦卡得像 PPT。

## 常見問題

**Q1：DeepSeek 優化後會不會把我的網站搞壞？**

**A1：** DeepSeek 會盡力優化且不影響功能，但畢竟它是 AI 模型，出錯的可能性還是有的。尤其當程式碼邏輯很複雜或存在很多隱藏依賴時，DeepSeek 可能會誤判。所以，部署到生產環境前，務必在測試環境進行充分的功能測試！

**Q2：這個方法適用於所有網站類型嗎？**

**A2：** 主要適用於靜態網站或前端程式碼相對獨立的動態網站。如果你的網站大量依賴後端渲染，或有複雜框架（像 React、Vue 等）的自動構建流程，那這個腳本可能只能處理最終生成的靜態資源。你可以把它整合到構建流程中，在打包後對最終文件進行優化。

**Q3：除了壓縮清理程式碼，DeepSeek 還有哪些騷操作？**

**A3：** DeepSeek 的潛力遠不止於此！它還能幫你生成圖片 `alt` 標籤、建議更優化的 HTML 結構、生成對 SEO 友好的 Meta 描述，甚至幫你檢查安全漏洞。只要你提示詞寫得夠清楚，DeepSeek 絕對能成為你網站開發和維護的超級助手！
