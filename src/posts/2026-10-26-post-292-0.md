## DeepSeek 建築條例「保姆級」智能檢索教程

要建立這個智能檢索系統，主要分為以下幾個步驟：

### 第一步：餵給 AI 「知識」，讓它「學習」

首先，你需要把所有跟香港建築條例相關的文件都收集齊活，像是 PDF 版的《建築物條例》、地政總署或屋宇署發的各種實務守則啊、通函啥的。這一步賊關鍵，畢竟 AI 的「腦子」裡裝啥，全看你餵給它啥。因為這些文件多半是 PDF，我們得想辦法把它們變成機器能讀懂的文字。要是掃描件，那必須先 OCR（光學字符識別）一下，保證文字沒毛病。說個我測試時發現的小秘密：如果把那些舊版 PDF 條例先 OCR 轉成文本，再丟給 DeepSeek API `v1.2` (截至 `2024年5月15日`) 去處理，效果會比直接上 PDF 強太多了，特別是對那些版面複雜、圖文混排的說明。

搞定文本後，咱們要把這些數據切成一小塊一小塊的（chunks），然後給它們生成「指紋」一樣的向量嵌入（embeddings）。這些「指紋」會被存到一個叫向量數據庫的地方，像 ChromaDB 或者 Pinecone 都是不錯的選擇。這麼做有啥好處呢？就是當你提問的時候，AI 就能在數據庫裡光速找到那些語義上最搭的文本塊，根本不用把整個資料庫掃一遍，那效率蹭蹭就上去了！你可以用 DeepSeek 自家的嵌入模型 API 來生成這些向量，或者選個開源的本地模型，比如用 Ollama 在自己服務器上跑。

### 第二步：問 AI 問題，讓它「開口」回答

數據都準備妥當了，接下來就是設計怎麼跟 AI 互動的界面了。一般來說，這塊會分成三部分：

1.  **你來提問：** 工程師或設計師把問題扔進去，比如：「現在的條例，工業大廈的消防通道到底要多寬啊？」
2.  **AI 去找答案：** 系統會把你提的問題轉化成「AI 語言」（向量），然後在那個向量數據庫裡瘋狂搜索，找出跟問題最搭的條文內容。這一步是 RAG 的『靈魂』所在，它保證 DeepSeek 只會讀到跟問題直接相關的上下文，而不是把整個資料庫都瞎翻一氣。
3.  **DeepSeek 給你答案：** 把 AI 剛才找到的相關內容當作「背景知識」，再和你原始的問題打包，一起丟給 DeepSeek API。打個比方，你可以這樣寫 prompt：「請根據以下香港建築條例內容，回答『工業大廈的消防通道到底要多寬啊？』，然後把相關條文編號也列出來：[檢索到的條文內容]」。DeepSeek 就會根據這些信息，給你一個明明白白、準確無誤的答案。

### 第三步：結果比對，但別忘了「人工審核」

DeepSeek 這傢伙，不僅能給你一個答案，你還能教它怎麼去比對。比如說，你可以直接問：「《建築物條例》第 123 條跟屋宇署 PNAP XXX 號通函裡關於防火門的要求，有啥一樣的，有啥不一樣的？」AI 就會根據它讀到的文件內容，給你把差異點一個個揪出來。這對於檢查新舊法規更新後是不是「打架」，或者兼容性如何，特別管用！

當然啦，AI 歸根結底是個工具人，它給出的答案，最後還是得靠經驗老道的專業人士去拍板。尤其是那些牽扯到法律責任的重大決策，AI 的結果只能當作參考，絕不能直接當成最終結論！不過話說回來，它能大大縮短你前期篩選和比對的時間，讓專業人員能把精力放在更高層次的審核和判斷上，這點絕對是槓槓的！

## 實用小竅門：讓你的 AI 更好用！

*   **切塊要夠精：** 怎麼把文件『碎屍萬段』（劃重點，這裡不是真碎屍啊！）對 AI 檢索的效果影響老大了。你可以試試按章節、按段落，或者固定字數來切，多試幾種看看哪種最給力。
*   **Prompt 玩出花：** 試著用不同的方式來寫 DeepSeek 的 prompt，引導它給出更精確、更有條理的答案。比如，你可以要求它每次都必須列出條文的出處和編號，讓答案看起來更專業。
*   **定期給 AI 「充電」：** 要建一套機制，定期更新向量數據庫裡的條例文件，這樣 AI 的「知識庫」才能保持最新，不會過時。
*   **跟內部系統『聯動』：** 把這個 DeepSeek AI 小助手無縫對接到公司現有的項目管理或文件管理系統裡，讓工程師們在日常工作時就能隨手調用，體驗感直接拉滿！
*   **隱私控看過來：** 如果數據隱私是你的頭等大事，那可以研究下在自己服務器上通過 Ollama 這類工具部署 DeepSeek 或其他開源 LLM。這樣一來，數據就完全不會離開你的網絡了。不過話說回來，這種方式可能要你準備性能更強的顯卡和網絡配置哦。

## 常見問題 (FAQ)

**Q1：DeepSeek 給的答案準不準？靠不靠譜？**

A1：DeepSeek 的準確度還是很能打的，特別是你給它喂了高質量、相關度高的「背景資料」（就是前面說的 RAG 架構）之後。但記住了，它可不是真律師也不是真建築師，它輸出的所有答案都只是給你參考，最後的拍板和驗證，必須得由有資質的專業人士來負責，尤其那些牽扯到法律或安全責任的項目，馬虎不得！

**Q2：公司那些機密文件丟給 DeepSeek API，會不會有隱私風險啊？**

A2：用任何第三方 AI 服務，都得仔細研究它的數據使用政策。通常來說，商業版的 API 都會承諾不會拿你的數據去訓練它們對外公開的模型。但如果你是超級隱私控，或者對數據安全有極高要求，那就可以考慮在本地部署開源 LLM 方案（比如 Ollama），這樣數據就完全在你掌握之中了。不過呢，這麼搞的話，技術難度和硬件投入肯定也要跟著水漲船高。

**Q3：這個 DeepSeek AI 方案，小公司也能玩得轉嗎？花錢多不多？**

A3：絕對沒問題！DeepSeek API 是按用量收費的，也就是說你用了多少 token 就付多少錢，初期投入很小。對中小企業來說，這簡直是福音！用更少的錢就能換來效率狂飆，根本不用去買那些死貴死貴的專業軟件，也不用額外請個專門的數據分析師。

**Q4：DeepSeek AI 能不能直接把人工查條例、比對的工作全都取代掉？**

A4：想多了，還不能完全取代。DeepSeek AI 更像是個超級輔助，它能大大減少那些重複又枯燥的機械活兒，把專業人士從『文件山』裡解放出來，讓他們專心去處理更複雜的判斷和設計決策。它最強的地方是『光速幫你找資料，然後擺在你面前』，但涉及到那些燒腦的語義解釋、多條例衝突時的優先級判斷，還有最後要背法律責任的時候，人類大腦的經驗和判斷，那還是無可替代的！
